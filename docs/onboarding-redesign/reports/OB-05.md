## 做了什么

**第 3 屏 Goals（可跳过）** `src/onboarding/founder/Goals.tsx`
- 三条虚构建议目标：Weekly events（1 / per week）、Active members（40）、External income（500 USD）。每条一个开关加一个数字步进器（− / + 按钮和可直接输入的数字框，点击区 44px）。默认开前两条。
- 点 Continue 才写回 `draft.club.goals`（保持现有 `Goal` 类型，`current` 为 0），先用 `validateGoals`（两到三条、目标为正数）。少于两条时在按钮上方显示错误（`role="alert"`）。
- 使命句默认折叠在 "Add a mission (optional)" 里，上限 300 字，直接写回 `draft.club.mission` 并设 `missionTouched`。
- Skip for now + 一行 skipHint；Back / Continue / Skip 都用 `useFlow()`。Skip 不改动草稿里原有的标准目标；Back 在选择有效时保存选择。
- 纯逻辑放 `founder/goals/suggestions.ts`（建议目标、行与目标互转、校验）。

**第 4 屏 Team（可跳过）** `src/onboarding/founder/Team.tsx`
- 每个岗位一行，只有两格：Role 和 Person。Person 留空 = Open position（placeholder 用 `copy.founder.team.open`）。
- 汇报关系从 `reportsToId` 带出，在每行最右显示一个小摘要（"↑ President"，总负责人显示 "Top"）；点开 `<details>` 才能改 Reports to（下拉，不能选自己下面的人，不会出现循环）和 Duties（textarea，≤ `MAX_DUTIES`）。改汇报关系后列表按"领导在前"重新排序。
- 可加岗位（`newRole`，标题自动不重复，加完光标落在新岗位）；可删岗位（`dropRole`，President 那行没有删除按钮，纯逻辑也拒绝删除）。
- **不问邮箱、电话、ASU ID。** 新名字会先清掉旧的演示邮箱，离开这一屏（Continue / Back / Skip）时由 `fillEmails` 自动生成 example.org 邮箱。一行说明用 `copy.founder.team.invited`。
- 组织图用现有 `OrgChart`，放在列表下方，随岗位名和汇报关系更新。
- 顶部 "AI suggested roles." 提示条：`draft.reading` 是 ready 且 `!draft.applied` 时出现，带 "Use these suggestions"，点了才套用（同 Setup.tsx 的 `structureFromRead` 逻辑，设 `applied=true`、`structureTouched=false`，使命句只在 AI 读出且未被手改时才换）。`reading` 为 reading 时显示 "Reading officer titles…"。**本屏不发任何 AI 请求。** 不自动套用（要用户点）。
- Continue 之前用 `validateRoles` + 每个人的 `validateProfile` + 重名检查；错误显示在按钮上方（`role="alert"`）。Skip 时如果当前岗位行不合法（比如清空了总负责人姓名），恢复成进入本屏时的样子，不把坏数据留给后面的 Confirm。
- 纯逻辑放 `founder/team/rows.ts`。

**文案**：只改了 `copy.ts` 里 `founder.goals` 和 `founder.team` 两个区块（加了 key，没动已有的 key 内容）。
**样式**：`src/styles/ob-05-goals-team.css`，只用 token；没有 `!important`、`transition: all`、裸毫秒。仅有的动效是开关圆点的 `transform`（`--dur-fast`，减少动效下为 1ms）；增删行、改数字不加动画。
