1. **Changing buffer changes no standard-workflow dates.** Engine fact, not UI defect. Tested actual v2/orgSteps, 3 event types ×260 dates, buffer 1 versus 7: **no clubDeadline changed**. Entire seedDemo(v2), 118 nodes: 0 changes; legacy seed: 18. Backward `schedule.ts` chooses earliest of official deadline minus buffer, target date, day before successor start. Every standard step has target anchors (e.g. 60 days early), always earlier, so buffer never wins. "Change buffer, dates immediately change" requires engine/workflow edits outside my allowlist.
   Wiring is **correct**: draft.buffer updates, preview regenerates, buffer passed as completeSetup's seventh parameter. Removing target anchors in an ASU-rule-only workflow proves wiring: buffer 3→5→7 brings several dates earlier, covered by unit/e2e. Added a known-engine-fact test that standard dates do not change; future engine changes will flag docs/tests needing updates.
   Decide: (a) accept buffer only affecting tight events/custom workflows and remove immediate-date-change acceptance; (b) separate engine/workflow package; (c) show another varying result beside buffer, e.g. ASU official deadline below dots. **Do not ask me to fake date changes.**
2. **npm run lint does not enforce motion rules on ob-*.css.** .stylelintrc.json bans bare durations/transition: all/!important/layout transitions only for dx-01…dx-99; ob gets base size/radius/layer/hex rules. Replacing var(--dur-fast) with 150ms in ob-06 still **passes `npm run lint:css`**. Config outside scope, so onboardingFirstEvent.test.ts checks same rules with intentional negative sample: "the real file passes the motion rules" fails for 150ms, passes restored token. Recommend adding src/styles/ob-0[4-9]-*.css, or ob-*.css excluding ob-00, to overrides[0].files.
3. **Default sentence yields past dates.** draft.tsx says "Plan Founder Dinner on Nov 19 …"; demo today Oct 31, standard workflow begins 60 days earlier in September. Draft outside scope. Three examples use spring Mar 5/Mar 26/Apr 16 with future dates; overdue dots use thick red ring/red date, same risk style/no new tokens. Recommend spring default sentence too.
