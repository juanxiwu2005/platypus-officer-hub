## 先说三件需要整合人决定的事

1. **拨缓冲，日期在标准流程里一个都不会变。** 这是引擎的事实，不是界面的问题。我用现在应用实际用的标准工作流（v2，`orgSteps`）试了 3 种事件 × 260 个日期，缓冲 1 天对 7 天，**没有任何一个节点的 `clubDeadline` 改变**（`seedDemo(v2)` 整个演示社团 118 个节点也是 0 个变；旧的 legacy 种子才有 18 个变）。原因：`schedule.ts` 的反推里，社团截止日取"官方截止日 − 缓冲""目标日"和"后续步骤开始前一天"里最早的，而标准工作流里每一步都有 `target` 锚（比如提前 60 天），目标日总是更早，缓冲从来排不上。策略文档写的"拨一下，日期当场变"在标准流程里做不到，除非引擎或工作流改（不在我的白名单里，我没动）。
   我做了什么：缓冲控件和预览**接线是对的**（拨一下写回 `draft.buffer`，预览用新缓冲重新生成，把缓冲当第 7 个参数传给 `completeSetup`）。我用"只靠 ASU 规则定日期"的工作流（把 `target` 锚去掉）证明接线有效：缓冲 3→5→7，多个节点的日期当场提前（单元测试和 e2e 都有）。同时加了一条"已知引擎事实"测试：标准工作流下缓冲不动任何日期；哪天引擎改了，这条会变红，提醒人来改测试和文档。
   需要你决定：(a) 接受现状（缓冲只在事件很紧或自定义工作流里起作用），把"日期当场变"从验收里拿掉；(b) 让引擎/工作流改（另开包）；(c) 缓冲旁边多显示一点别的会变的东西（比如每个点下面加 ASU 官方截止日）。**不要让我伪造日期变化。**
2. **`npm run lint` 管不到 `ob-*.css` 的动效规则。** `.stylelintrc.json` 里"不准裸毫秒、`transition: all`、`!important`、布局属性过渡"的规则只对 `dx-01…dx-99` 文件生效，`ob-*.css` 只吃到基础规则（字号、圆角、层级、hex）。我试过：把 `ob-06-first-event.css` 里的 `var(--dur-fast)` 改成 `150ms`，`npm run lint:css` **仍然是绿的**。我没权限改 `.stylelintrc.json`，所以在自己的单元测试里用同一套规则去检查 ob-06 的样式文件，并附了"故意违规会变红"的样本（同样改成 `150ms`：`src/test/onboardingFirstEvent.test.ts` 的 "the real file passes the motion rules" 变红，改回来变绿）。建议整合人把 `overrides[0].files` 加上 `src/styles/ob-0[4-9]-*.css`（或 `ob-*.css` 去掉 `ob-00`），一次管住所有 ob 包。
3. **默认句子里的日期已经过了。** `draft.tsx` 的默认句子是 "Plan Founder Dinner on Nov 19 …"，演示今天是 10 月 31 日，标准工作流从事件日往前推 60 天，所以前几个点的日期是 9 月，都在今天之前。我没改 draft（不在白名单）。我做了两件事：三个示例句子选了春季日期（Mar 5、Mar 26、Apr 16），日期都在今天之后；日期已经早于今天的点，画成红色粗环 + 红色日期（和产品里"有风险"的点一致，不新增 token）。建议 draft 的默认句子也换成春季日期。

  - 进度链：用 `completeSetup` 预览（`draft.club`、`draft.steps`、`draft.inviteCode`、`draft.buffer`）得到节点，按社团截止日排序，取前 6 个（上限 `MAX_DOTS = 6`，代码里再封顶 8），圆点 + 线，下面是步骤名和日期。日期**只**来自节点的 `clubDeadline`。

  - 改了句子之后（还没再按 Plan it）：链变淡，出现 "Press Plan it to update the steps."，Continue 关闭，避免用旧计划配新句子。

## 怎么验收（点哪里）

1. 打开 `/#/welcome/founder/first-event`（本机：先 `npm run build && npm run preview`，或 `npm run dev`）。
2. 点 **Welcome mixer**，再点 **Plan it**：一条连着线的圆点链在眼前画出来，每个点下面是步骤名和日期。**Continue** 变成可点。
3. 点 **Club buffer** 的 1 / 5 / 7：按钮高亮，写回草稿。（标准流程里日期不会变，见上面第 1 条。）
4. 点 **Event details** 展开，把日期改成过去的日子：Continue 变灰、出现提示、链消失；改回将来的日期，链回来。
5. 点 Back：回到上一屏（Team）。再点 Plan it 多次：每次立刻重画。
6. 系统开"减少动效"：链一下子整张出现。

## 测试结果

- `npm run lint`：绿。`npm run build`：绿。
- `npm test`：863 条，862 通过；唯一失败是已知脆弱的 `src/test/engine.test.ts` "no change ever makes a step start after its own club deadline"（5 秒上限）。另外有两次整套运行时 `forecastOnce.test.tsx` 等也因机器负载超时，**单独**加 `--testTimeout=30000` 重跑 `engine.test.ts` 和 `forecastOnce.test.tsx`：54 条全过。没有改这些测试。
- `PW_PORT=5206 PW_STORAGE_PORT=5306 WORDS_PORT=5406 npx playwright test e2e/ob-06-first-event.spec.ts --project=desktop --project=mobile`：31 通过，1 跳过（"手机上 ≥44px"这条在桌面项目里跳过，手机项目通过）。
- e2e 覆盖：最快路径（并且页面上的日期与在 Node 里用规则引擎算出的完全一致）、返回、不是活动的句子、缓冲（自定义规则型工作流下日期变；标准工作流下不变）、Event details 与过去日期、改句子后 Continue 关闭、字数 ≤ 60（提问前、画完后各查一次）、手机 44px 与无页面横向滚动、axe（浅色、深色、详情展开）、减少动效、逐帧采样、打断、全程没有 `/api/org`、`/api/workspace` 请求，也没有 `/api/command`、`/api/health` 以外的请求。
- **逐帧采样**：把减少动效切回"不减少"，在页面里按 Plan it 后每帧读各点的 opacity 和各线的 scaleX：看到过 0 到 1 之间的值，点按顺序变满，全部画完 < 800ms，结束后动画名变回 `none`。减少动效下第一帧所有点 opacity 为 1、`animation-name` 为 `none`。
- **反向验证**：把 ob-06 样式里一个时长改成裸 `150ms`：`npm run lint:css` 仍绿（见第 2 条），`onboardingFirstEvent.test.ts` 变红；改回后变绿。
