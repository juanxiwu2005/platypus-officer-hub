# OB-07 社员预览前半：Invitation + You + Reminders

分支：`design/ob-07-member-invitation`（本地，未推送）。执行者：Claude。

## 做了什么

三个社员屏（流程 B 的第 0–2 屏）都做好了，替换了 OB-01 的空壳：

- **Invitation**：顶部 Demo 条 "Previewing as Maya Chen · Change"；大标题社团名；"Alex Rivera invited you to be **Treasurer**"；放大的角色卡（角色、Reports to、职责最多 3 行）；三条"你会得到什么"；一句信任说明；按钮 Continue（贴底）。
- **无效邀请**：`?invite=` 和这个浏览器里的邀请码不一致，或 `?person=` 找不到人，或社团里没人，都显示 `copy.invalidInvite` + 一行 Demo 提示 + 两个下一步（"Use this browser's invitation" 回到有效的邀请；"Go to Today"）。链接里没有 `?invite=` 时，当作"这个浏览器里的邀请"，直接显示。
- **You**：姓名、邮箱已从该干部的记录预填，可改；Continue 时用 `validateProfile`（姓名非空、example.org 邮箱）和 Settings 一样的"不能和别人重名"检查；错误是 `role="alert"`。"Not you?" 打开顶部 Change 选择器并把焦点放进去。Demo 条在这一屏多一行 "Fictional demo. Choosing a name does not verify an identity."（只在这一屏出现一次）。
- **Reminders**：渠道三个单选行（WhatsApp / SMS / Email，原生 radio，整行可点，≥44px）；**只有选 WhatsApp 或 SMS 才出现电话输入**，并写用途（`phoneWhy`）；电话格式沿用 `validateProfile`（可留空，555-01xx）；**不问 ASU ID**；时间 Morning / Evening 分段控件；静默时段一行字；下面一条随选择即时变化的示例提醒气泡（WhatsApp 绿色圆角带尖、SMS 灰色靠右、Email 卡片带左边线；文字随时间换 "this morning / this evening"；标了 "Example"，纯展示，不发送）。必填，没有 Skip。
- 动效：选择不加位移；气泡内容变化是纯淡入（opacity，`--dur-fast`），再点一下立刻重新开始、不排队；减少动效下 token 变 1ms，直接切换。
- 主按钮栏 `position: sticky`，贴在窗口底部（页面比窗口矮时也靠底）；只有这一条栏有模糊，减少透明度/不支持时回退实心；手机上 Continue 占满、Back 在左边。
- Change 选择器：Demo 条里的小 `<select>`，列出该社团所有干部（"Maya Chen · Treasurer"），默认第一个非 president 的人；Esc 或失焦收起，焦点回到 Change。

## 怎么验收（点哪里）

1. 先打开任何页面，让样例社团生成；然后打开 `/#/welcome/member/invitation`（不需要 `?walkthrough=1`，路由本来就在）。
2. 看社团名、"Alex Rivera invited you to be Treasurer"、角色卡；点 **Change** 换成 Jordan Patel，角色卡变成 Events lead。
3. **Continue** → `/#/welcome/member/you`：姓名邮箱已填；把邮箱改成 gmail 再 Continue 看报错；点 **Not you?** 看选择器。
4. **Continue** → `/#/welcome/member/reminders`：点 Email（电话消失）、点 WhatsApp / SMS（电话出现，写着用途）；切 Morning / Evening 看气泡变化。Continue 去到 `/#/welcome/member/busy-weeks`（OB-08 的占位）。
5. 无效邀请：`/#/welcome/member/invitation?invite=nope`。指定干部：`/#/welcome/member/invitation?person=sam`。

## 暂存字段（给 OB-08）

sessionStorage 的 key **`platypus.v1.onboarding.member`**，值是 JSON（只存下面这些字段，读取时多余的会被丢掉，见 `src/onboarding/member/invitation/choice.ts` 的 `parseChoice`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `v` | `1` | 版本 |
| `personId` | string | 预览的干部 id（Invitation 的 Continue 就会写入；换人会清掉其他字段） |
| `name` | string，可选 | You 屏的姓名（编辑或确认后写入；总是这位干部自己的虚构姓名或你改的） |
| `email` | string，可选 | **只在和干部记录不同（用户改过）时才有**；没有就用 `person.email` |
| `phone` | string，可选 | **只在渠道是 WhatsApp/SMS 且填了时才有**；选 Email 会删掉；没有就是空 |
| `channel` | `"whatsapp" \| "sms" \| "email"`，可选 | 没访问过 Reminders 就没有，用 `person.channels[0]` |
| `remindAt` | `"morning" \| "evening"`，可选 | 同上，缺省用 `person.remindAt` |

OB-08 可以直接 `import { readChoice, MEMBER_KEY } from "./invitation/choice"` 和 `previewPatch(person, stored)`（`invitation/profile.ts`，已按这些规则合并并校验，`asuId` 恒为空）。**注意"不存姓名之外的个人信息"**：邮箱和电话只在用户自己输入了和记录不同的值时才暂存（否则 OB-08 无法保存用户的修改）；都是虚构数据；sessionStorage 只在这个标签页里，关掉就没了。如果 Juanxi 要求更严（电话/邮箱也不暂存），改法是 OB-08 的 Done 屏不用这些字段，请整合人决定。

## 没验证的

- 真机手指、iOS Safari、Android 浏览器（只在 Chromium 的 Pixel 7 / 桌面模拟里测过）。
- 屏幕阅读器的实际朗读（只有 axe 扫描通过；气泡区是 `aria-live="polite"`，选一次渠道会读一次，没有真人听过）。
- 深色模式只跑了 axe 对比度和一次截图检查；没有逐像素对比。
- 极长的自定义职责（接近上限 `MAX_DUTIES`）只靠 3 行截断，没有在页面上提供"展开"。
- OB-08 的 Done 屏读取暂存字段的部分（不是本包范围）。
- 没跑完整 `npm run check`（按并行包规则交给整合人）；没跑 `npm run words`（本包的页面不在它的页面清单里）。

## 字数（一眼看到的，`<main>` 内可读英文词）

- Invitation 最多 **约 55 词**（含 Demo 条、社团名、角色卡、三条、信任句、Continue），**超过了任务里写的 40，按策略里"邀请屏 ≤60"处理**：策略要求这一屏同时有角色卡 + 三条 + 信任说明，不可能压到 40 而不删内容。测试限制是 ≤60。需要整合人确认。
- You ≤40（实测约 24）。
- Reminders 在选 Email（没有电话）时 ≤40（测试里量过）；选 WhatsApp/SMS 时电话标签和用途再多约 13 词，会到约 50。电话那一段是用户选了才出现的，算"点出来的"，不算一眼看到的；但默认渠道是干部自己的第一选择（Maya 是 WhatsApp），所以默认打开时就会看到电话。需要整合人确认怎么算。
