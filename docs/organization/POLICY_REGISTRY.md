# 政策目录（单一事实来源）

更新时间：2026-10-30。目录的代码正本是 `src/policy/catalog.ts`；查询、AI 上下文和日期引擎入口在 `src/policy/query.ts`。页面、提示词、手工工作流不得另写一份政策文本或截止日。

本轮从用户提供的 2026-10-29 Rules Index、Full Rules Archive 和 Event Workflow Standard Template 导入：

- 24 条工作流政策（START / PLAN / VENUE / SPECIAL / FUND / CLOSE）；
- 每条的适用条件、证据、来源、是否需实时确认、硬性或建议提前期；
- 25 个已被工作流引用的来源目录项。Rules Index 共列出 64 个来源快照；其中尚未转成工作流政策的来源仍是复核资料，新增为可执行政策前必须补入带来源的目录记录。

## 使用边界

1. `hardDeadline()` 只返回官方硬截止日。活动规模只能影响建议提前期，不能放大官方截止日。
2. `applicablePolicies()` 对未知条件采取保守做法：不会假装某项特殊政策适用，也不会告诉用户该项不适用；应要求补齐活动信息或回到实时来源。
3. `policyContextForAi()` 是 AI 的唯一政策上下文，带来源、范围与证据等级。AI 只能引用返回的 ID；没有匹配政策时必须说明需人工确认。
4. `user_provided`、`access_restricted`、`historical` 材料永远不覆盖当前公开官方来源。`needs_live_confirmation` 表示部署前或实际提交前必须重查来源。
5. 跨社团经验数据与政策分离。未来共享数据只能作为非约束性的经验层，必须带组织授权、匿名化、更新时间和撤回机制，不能修改本目录的官方政策。
