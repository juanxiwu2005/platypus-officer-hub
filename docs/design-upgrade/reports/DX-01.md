## Corrections (2026-11-01, discovered during stage 1)
1. **Screenshot dimensions were wrong.** This and DX-02 reports said “64 screenshots, desktop 1440×900, mobile 390×844,” but all were 1280×720: script put dimensions at top level of context options, while Playwright recognizes only `viewport`. The “mobile screenshots” were therefore not mobile-width. **Fixed** (`scripts/dx-shots.mjs`, stage 1 commit): desktop 1440×900, mobile 390×844 (2×, images 780×1688).
2. **Byte comparison was too strict.** Rendering the same build twice produces 4 differing mobile images (max about 9,500 pixels, concentrated in dropdown text in mobile header); criterion is therefore “changed-pixel count exceeds noise ceiling (about 15,000 pixels, ≈1.1%),” not byte identity. Script now saves only after “two screenshots 200ms apart match exactly,” reducing unstabilized captures, but cannot remove mobile-header subpixel noise.
3. **Reverified stage 0 with corrected script** (original `dx/baseline` vs merged DX-01+DX-02):among 64 images, **32/32 desktop images identical**; 27/32 mobile identical, remaining 5 within noise (max 14,872 pixels≈1.1%). Conclusion remains “stage 0 did not change appearance,” now based on correct mobile dimensions.
