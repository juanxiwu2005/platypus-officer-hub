# Report: DX-22 flowchart nodes move with transform + spring settling

- Branch: `design/dx-22-flow-motion` · Implemented by Claude, 2026-11-01 · Rollback: R2

## Changes
- `src/components/flow/MetroChart.tsx`: steps/start/end stops use CSS variables `--x`, `--y` and `transform: translate(...)` instead of `left/top`. New `placeKey` (step columns/rows, excluding status/color) adds `is-settling` to `.metro` for one spring duration when changed (step/route additions/removals); resize/first paint do not trigger it. Drag ◆ insertion marker/ghost still use pointer-following `left/top` (unanimated).
- New `src/lib/motion.ts`: `tokenMs`, `prefersReducedMotion`.
- `src/styles/dx-22-flow-motion.css`: default `transition: none`; with `is-settling`, steps glide via `--spring-ui` (`--spring-ui-dur`, 450 ms), all connectors dim to 35% then recover, avoiding moving dots/jumping lines; `.m-gap.is-near` scales instead of changing dimensions. Reduced motion places everything immediately.

- With `flow-edit` (context menu/line drag), `events`, `feel` (zero hover delay), `a11y` (desktop+mobile): **110 passed/13 intentional skips/0 failed**.
- **Negative verification:** clearing styles fails 4 tests.
- `npm run lint` (style guard included) and typecheck passed; full integrated `npm run check` in stage 4 handoff, `docs/PROGRESS.md`.

## Notes
- **An unexpected fact directly affects this package's value:** this graph “preserves approximate time positions rather than enforcing strict sequence” (`flow-edit.spec.ts` comment), so reordering steps, changing event date, or adding a step after another **does not move existing dots** (confirmed frame-by-frame). Few current cases reposition existing steps. This package correctly handles movement when it occurs (transform, spring, synchronized lines), but **you may rarely see movement in today's layout**; it becomes useful automatically if DX-24 or later changes the layout.
- Tests therefore verify style/rules separately instead of recording actual gliding.
- Initial bulk replacement also converted ◆ marker `left/top` to variables, mispositioning it; reverted after discovery.
