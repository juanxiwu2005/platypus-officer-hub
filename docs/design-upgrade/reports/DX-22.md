# 报告：DX-22 流程图节点用 transform 移动 + 弹簧落位

- 分支：`design/dx-22-flow-motion`　执行：Claude，2026-11-01　回滚：R2

## 做了什么
- `src/components/flow/MetroChart.tsx`：步骤和起止站点不再用 `left/top`，改为 CSS 变量 `--x`、`--y`，由 CSS 用 `transform: translate(...)` 放置。新增 `placeKey`（每个步骤在图里的列和行，不含状态/颜色）：它变了（有人加/删步骤、路线增减）就给 `.metro` 加 `is-settling` 类，持续一个弹簧的时长；窗口缩放和第一次绘制不会触发。拖动时的 ◆ 放置点和虚影仍然用 `left/top` 跟着指针（不动画）。
- `src/lib/motion.ts`（新）：`tokenMs`、`prefersReducedMotion`。
- `src/styles/dx-22-flow-motion.css`：默认 `transition: none`；`is-settling` 时步骤用 `--spring-ui` 滑行（`--spring-ui-dur`，450ms），连线整体变淡到 35% 再恢复，这样点和线不会再"点在滑、线在跳"；`.m-gap.is-near` 改用 `scale` 放大而不是改宽高。"减少动效"下全部直接到位。

## 证据
- 新测试 `e2e/dx-22-flow.spec.ts`（电脑，6 个）：步骤的 `left/top` 都是 0 且用 `transform` 放置；**样式**——有 `is-settling` 时一个步骤平滑滑到新位置（中间有 >3 个位置），没有时直接到位；**规则**——真实添加一个步骤时 `is-settling` 出现、线条变暗到 0.3–0.9 之间、之后恢复为 1 且类被摘掉；窗口变窄不触发滑行；放置点用缩放；"减少动效"下不触发。
- 加 `flow-edit`（含右键菜单、拖线）、`events`、`feel`（流程图悬停卡零延迟）、`a11y`（桌面 + 手机）：**110 通过 / 13 按设计跳过 / 0 失败**。
- **反向验证**：清空本包样式，4 个测试变红。
- `npm run lint`（含样式守卫）和类型检查通过；阶段合并后的完整 `npm run check` 结果见 `docs/PROGRESS.md` 的阶段 4 交接。

## 要注意的地方
- **一个我之前没料到的事实，直接影响这个包的价值**：这个图"保留近似的时间位置，不强制严格的先后顺序"（`flow-edit.spec.ts` 里的注释），所以交换步骤的顺序、改活动日期、在一个步骤后面添加一个步骤，**都不会让已有的点移动位置**（我逐帧采样确认过）。现在真正会让已有步骤换位置的情况很少。所以这个包是把"会动的时候"做对了（transform、弹簧、线条同步），但**在今天的布局里你可能很少看到它动**；等 DX-24 或以后改了布局，它会自动派上用场。
- 因此测试拆成"样式"和"规则"两半，分别验证，而不是录一段真实的滑行。
- 我的第一版批量替换把 ◆ 放置点的 `left/top` 也换成了变量，会让放置点错位，发现后改回。
