# Report: DX-26 Partners board dragging (reuse DX-24 tools)

- Branch: `design/dx-26-crm-drag` · Implemented by: Claude, 2026-11-01 · Rollback: R2 (revert this package only; `dragSort.ts` unaffected)

## Changes
- `src/pages/Partners.tsx` (Board only): replace native `draggable` / `onDragStart` / `onDragOver` / `onDrop` with DX-24's `useDragSort` (**call only; `dragSort.ts` unchanged**). Columns gain `data-drop-col`, board gains `data-drag-scroll`, cards receive `cardProps` only with permission.
- Drop and keyboard both use the same `moveStage()`, the original `updateContact` action: **no store/schema/`SCHEMA_VERSION` changes**.
- Permissions unchanged: only `canEditContact(state, c)` cards drag (others lack drag markers and `cardProps`); `onDrop` and `onNudge` recheck permissions as a second guard. Unauthorized `visibility: "leads"` contacts are already absent from `rows`, hence invisible on the board.
- Existing stage `select` retained as keyboard/mobile fallback.
- Card name changed from `<button>` (dragSort.ts never starts dragging on buttons) to `<span role="button" tabIndex=0>`, matching Tasks; Enter/Space still open details, screen readers still see a button.
- `Alt+←/→` moves to adjacent stages, with `aria-live` "Moved … to …."; left from the first stage announces "It cannot move that way.".
- `src/styles/dx-26-crm-drag.css`: dragged card lifts (`--elev-2` shadow, accent border, tracks pointer without easing); target stage has accent outline + light background; card text selection disabled while dragging. Tokens only, no `!important`.

## Intentional differences from Tasks
Contacts have **no order within a stage** (fixed sorting), so **no making room** or "insert before card" announcement; only outline the target column. Dropping in the current stage does nothing (no empty update).
