# 报告：DX-26 Partners 看板拖拽（沿用 DX-24 的工具）

- 分支：`design/dx-26-crm-drag`　执行：Claude，2026-11-01　回滚：R2（只撤本包即可；`dragSort.ts` 不受影响）

## 做了什么
- `src/pages/Partners.tsx`（只动 Board 视图）：去掉浏览器自带的 `draggable` / `onDragStart` / `onDragOver` / `onDrop`，换成 DX-24 的 `useDragSort`（**只调用，没改 `dragSort.ts`**）。列加 `data-drop-col`，看板加 `data-drag-scroll`，卡片按权限才加 `cardProps`。
- 落点和键盘都走同一个 `moveStage()`，也就是原来的 `updateContact` 动作：**没碰 store、没改数据结构、没改 `SCHEMA_VERSION`**。
- 权限不变：只有 `canEditContact(state, c)` 为真的卡片能拖（无权限的卡片没有拖拽标记，也没有 `cardProps`）；`onDrop` 和 `onNudge` 里再查一次权限，双保险。`visibility: "leads"` 的联系人对没权限的人本来就不在 `rows` 里，所以看板里也看不到。
- 卡片上的"阶段 `select`"保留，是键盘和手机的备用路径。
- 卡片名字原来是 `<button>`：按在按钮上不会开始拖拽（`dragSort.ts` 规定的），所以改成 `<span role="button" tabIndex=0>`，和 Tasks 看板同一种做法；回车/空格仍然打开详情，读屏器看到的还是"按钮"。
- `Alt+←/→` 把联系人移到相邻阶段，`aria-live` 播报 "Moved … to …."；第一个阶段再往左播报 "It cannot move that way."。
- `src/styles/dx-26-crm-drag.css`：被拖的卡片抬起（`--elev-2` 阴影、强调色边框、跟手无缓动）；手指下的阶段列用强调色描边 + 浅底色；拖动时禁用卡片文字选择。全部用 token，没有 `!important`。

## 和 Tasks 看板不一样的地方（有意的）
联系人在一个阶段里**没有顺序**（列表按固定规则排），所以这里**不让位**、也不播"插到哪张卡前面"——只描边目标列。落在原来的阶段 = 什么都不做（不会写入一次空更新）。

## 证据
- 新测试 `e2e/dx-26-crm-drag.spec.ts`（桌面 6 个，手机跳过，手机走阶段 select）：拖到 Warm 后阶段改变并存进 localStorage；拖动中卡片有阴影、目标列有强调色描边；Esc 取消和松手在看板外都**不改数据**；点击名字仍打开详情、阶段 select 仍可用；`Alt+→` 移动并播报、第一阶段 `Alt+←` 播报"不能"；无权限（maya）看到的"不可编辑"卡片拖不动、数据逐字节不变、select 禁用；leads 联系人对 maya 不在看板里。

## 要注意的地方 / 没验证的
- 真实手指：只有 DX-24 的合成触摸事件测过逻辑，Partners 沿用同一份代码，没单独测真机。
- 容器里 Playwright 浏览器路径变了（`/opt/pw-browsers/chromium-1243/chrome-linux64/chrome`），本地跑测试要设 `PW_CHROMIUM`；这是环境问题，不是代码问题。
- 旧样式 `.crm-card[draggable="true"] { cursor: grab }` 因为卡片不再有 `draggable` 属性而失效，本包的 CSS 里改成 `[data-editable="true"]` 补上抓手光标（无权限卡片仍是普通光标）。
