# Report: DX-23 translucent top bar + shadow-level tokens

- Branch: `design/dx-23-glass-topbar`　Executed by Claude, 2026-11-01　Rollback: R1 (comment DX-23 in `index.css`; harmless scroll state in `TopBar.tsx` remains) or R2

## Changes
- `TopBar.tsx`: add `data-scrolled` to `<header>` (true when page scroll exceeds 0).
- `src/styles/dx-23-glass-topbar.css`: top-bar background = 80% page background + `backdrop-filter: blur(16px) saturate(1.4)`, revealing content scrolling underneath; bottom border **appears only after scrolling**. Three shadow tokens `--elev-1/2/3` (stronger in dark mode; only `rgb(0 0 0 / x)`, no hex), applied to `.menu`, `.m-menu`, `.owner-suggest`, `.panel`, `.toast`, floating `.rail`. **No blur** on menus, hover cards, detail panels, content cards (stacked translucency reduces text clarity). Solid fallback when `backdrop-filter` unsupported, reduced transparency enabled, or increased contrast enabled (also a distinct border for the latter).

## Evidence
- New desktop `e2e/dx-23-glass.spec.ts`, 6 cases: top-bar background opacity between 0.6–1 and `backdrop-filter` includes `blur(16px)`; after inserting 3000px-tall content, top has `data-scrolled="false"` and transparent border, scroll to 400px gives true/visible border, return removes it; increased contrast yields opaque background/no blur/border; three shadow tokens exist, Demo menu uses `--elev-2` (light `rgba(0,0,0,.1)`, dark `.45`).
- **Negative validation:** emptying package styles makes 5 of 6 tests fail.
- `npm run lint` (style guards included) and type checks passed; full post-integration `npm run check` is in the stage-5 handoff in `docs/PROGRESS.md`.

## Caveats
- **Reduced transparency cannot actually be enabled in this browser:** Playwright Chromium does not recognize `prefers-reduced-transparency`. The test inspects the rule itself (media query exists, `.topbar` becomes solid, `backdrop-filter: none`), checking computed values only when supported. `more contrast` was genuinely enabled and tested.
- No material styling for 20b bottom bar (20b not implemented).
- Dark-mode text contrast after blur was not measured separately: top-bar text uses `--ink` above 80% `--surface` + 20% scrolling content; integrated `a11y.spec.ts` includes automated contrast coverage.
