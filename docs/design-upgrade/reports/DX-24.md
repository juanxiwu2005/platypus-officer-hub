# 报告：DX-24 看板指针拖拽 + 让位 + 弹簧 + 键盘

- 分支：`design/dx-24-board-drag`　执行：Claude，2026-11-01　回滚：R2（DX-26 依赖其中的 `dragSort.ts`，先撤 DX-26）

## 做了什么
- 新文件 `src/lib/dragSort.ts`：一个通用的"指针拖拽"工具（不认识任务）。卡片用 `transform` **一比一跟手**，并保持你抓它的位置；鼠标/笔移动 8px 才开始，手指要按住 250ms 才开始（所以滑动仍是滚动）；窗口级监听，所以快速移出卡片也不会丢；拖到看板边缘 40px 内自动横向滚动；松手后卡片用弹簧从松手位置滑进新位置（FLIP，WAAPI）；`Esc` 或松手在看板之外，卡片弹簧回原位；**Alt + ←/→** 把聚焦的卡片移到相邻列，并通过 `aria-live` 播报 "Moved “…” to …"，移动后焦点留在卡片上。
- `src/pages/Tasks.tsx`（只动看板）：去掉浏览器自带的 `draggable` 和 `onDrag*`；列加 `data-drop-col`、卡片加 `cardProps`；落点仍然走原来的 `move()`（权限规则和 `moveTask` 没变，**没碰 store、没改 `SCHEMA_VERSION`**）；插入点之后的卡片下移让位（`.is-shifted`）；**折叠列只有被卡片"停留"约 350ms 才展开**，快速掠过不展开（否则版面会在你眼皮底下乱动）。
- `src/styles/dx-24-board-drag.css`：被拖的卡片抬起（阴影、强调色边框）；让位的卡片 `translateY`；拖动时全局禁止选字。

## 证据
- 新测试 `e2e/dx-24-drag.spec.ts`（电脑 10 个）：卡片精确跟手（移动 120×90 就位移 120×90，且是 `transform: matrix(1,0,0,1,120,90)`）；不到 8px 不算拖动；其他卡片让位、目标列描边；松手后任务移到新列；Esc 取消且**数据完全不变**；松手在看板外面回原位、**随后单击仍能打开详情**；Alt+→/← 移动并播报；"手指要按住才拖，快速滑动不拖"（用触摸类型的指针事件模拟）；权限不允许时要么移动、要么有提示，不会悄悄半移动；折叠列"停留才展开、掠过不展开"；"减少动效"下仍能跟手和放下，但不滑动。
- 回归（桌面 + 手机）：现有的 `tasks`（含原来的 `dragTo` 拖放，没有改过一个字）、`rehearsal`、`touch`、`a11y`、`activity-workspace`、`word-budgets`、`dx-16-board`、`dx-21-headers` 与本包合起来多轮 **122 通过**，最后一轮 `dx-24`+`dx-16`+`tasks` **38 通过 / 16 按设计跳过 / 0 失败**。没有给任何测试加 `force: true`。
- **反向验证**：清空本包样式，只有 1 个测试变红（让位那个）——因为拖拽逻辑在 TS 里，样式只管外观，这是预期。
- `npm run lint`（含样式守卫）和类型检查通过；阶段合并后的完整 `npm run check` 结果见 `docs/PROGRESS.md` 的阶段 5 交接。

## 要注意的地方
**测试和实际使用抓到的问题（都已修）：**
① 我第一版测试用了猜的任务 id，读到 `undefined`，"数据不变"的断言其实什么都没比较（`undefined === undefined`）——改成从页面读真实 id，并加了"记录确实存在"的断言；
② **键盘移动后焦点丢了**：卡片被重建到新列，焦点留在被卸载的旧元素上，第二次 Alt+方向键无效——现在移动后把焦点放回新卡片，并让卡片从旧位置滑过去；
③ **松手在看板下方的空白处也被算成"放在这一列末尾"**，悄悄改了排序——命中判断现在要求横纵坐标都在列里；
④ **拖过空列时它们一路展开，把版面挤动**，松手前最后一次判断用的是挤动之前的布局——先加了"版面变了就按同一个指针位置重新判断"，再改成"停留 350ms 才展开"，这才是对的（也解决了 DX-16 留下的"已知局限"）；
**没有验证的**：真实手指（只用触摸类型的合成事件测了逻辑）；拖动过程中源列留下的空位在跨列放下后才合拢；同一列内上下换序时让位量会多算一个空位；Safari。
