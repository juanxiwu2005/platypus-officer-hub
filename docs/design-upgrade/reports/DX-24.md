# Report: DX-24 Board pointer dragging + displacement + springs + keyboard

- Branch: `design/dx-24-board-drag`　Executed by Claude, 2026-11-01　Rollback: R2 (DX-26 depends on `dragSort.ts`; revert DX-26 first)

## Changes
- New `src/lib/dragSort.ts`: generic pointer-drag utility with no task knowledge. Cards **track the pointer one-to-one** via `transform`, retaining the grab offset. Mouse/pen starts after 8px; touch requires a 250ms hold (so swipes still scroll). Window-level listeners retain fast movements outside cards. Auto-horizontal scrolling within 40px of Board edges. On release, spring from release point into new position (FLIP, WAAPI); `Esc` or release outside Board springs back. **Alt + ←/→** moves a focused card to the adjacent column, announces "Moved “…” to …" through `aria-live`, and retains focus.
- `src/pages/Tasks.tsx` (Board only): remove native `draggable`/`onDrag*`; columns gain `data-drop-col`, cards `cardProps`; drop still uses original `move()` (permissions/`moveTask` unchanged; **store and `SCHEMA_VERSION` untouched**). Cards after insertion point move down (`.is-shifted`). **Collapsed columns expand only after hovering a card for about 350ms**; passing quickly does not expand, avoiding shifting layout during dragging.
- `src/styles/dx-24-board-drag.css`: lifted card shadow/accent border; displaced cards `translateY`; disable text selection globally during drag.

## Evidence
- New desktop `e2e/dx-24-drag.spec.ts`, 10 cases: exact pointer tracking (120×90 movement gives 120×90 displacement, `transform: matrix(1,0,0,1,120,90)`); under 8px is not dragging; other cards shift/target column outlined; release moves task; Esc cancels with **identical data**; release outside restores position and **a subsequent click still opens details**; Alt+→/← moves/announces; touch hold versus quick swipe (touch-type synthetic pointer events); unauthorized moves either move or show a message, never silently half-move; collapsed columns expand on dwell, not pass-through; reduced motion still tracks/drops without sliding.
- Desktop/mobile regression: existing `tasks` (original `dragTo` unchanged verbatim), `rehearsal`, `touch`, `a11y`, `activity-workspace`, `word-budgets`, `dx-16-board`, `dx-21-headers` plus package tests: **122 passed** across rounds; final `dx-24`+`dx-16`+`tasks`: **38 passed / 16 intentional skips / 0 failures**. No `force: true` added.
- **Negative validation:** emptying package styles fails only 1 test (displacement), as expected because drag logic is in TS and styles control appearance.
- `npm run lint` (style guards included) and type checks passed; full post-integration `npm run check` is in the stage-5 handoff in `docs/PROGRESS.md`.

## Caveats
**Issues caught by tests and actual use (all fixed):**
① My initial test guessed a task ID, read `undefined`, and compared nothing with its unchanged-data assertion (`undefined === undefined`); now reads the real ID from the page and asserts the record exists.
② **Keyboard moves lost focus:** the card remounted in the new column while focus stayed on the unmounted element, breaking the second Alt+arrow. Now refocus the new card and animate it from the old position.
③ **Releasing in blank space below Board counted as a drop at the column end**, silently changing order; hit testing now requires both coordinates inside the column.
④ **Passing over empty columns expanded them all and shifted layout**, while the final pre-drop test used old geometry. First added rechecking the same pointer position after layout changes, then the correct 350ms dwell expansion (also fixes DX-16's known limitation).
**Unverified:** real fingers (logic tested only with synthetic touch-type events); source-column gap closes only after cross-column drop; same-column vertical reorder overcounts displacement by one gap; Safari.
