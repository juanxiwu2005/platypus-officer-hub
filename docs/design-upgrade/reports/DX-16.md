# Report: DX-16 Tasks Board layout: narrow empty columns, visible Done, card hover

- Branch: `design/dx-16-board-layout` · Implemented by Claude, 2026-11-01 · Rollback: R2 (DX-21/DX-24/DX-26 depend on it; revert them first)

## Changes
- `src/pages/Tasks.tsx` (Board only): empty columns collapse to 56 px strips (vertical heading, "+"), with a large expand/collapse button (`aria-expanded`, e.g. "Not claimed, no tasks. Show column", Tab-accessible). Dragging over, clicking strip, or adding a task expands them. `+ Add task` accessible name **unchanged** (added `aria-label="+ Add task"`), required by existing tests. All six `h2` retained.
- `src/styles/dx-16-board-layout.css`: desktop flex Board, `flex: 1 1 164px`, minimum 120 px, collapsed 56 px; column-width transition `--dur-base` (**only animated layout property in this package**); minimum height `min(60vh, 520px)` for adequate drop targets; accent border on hover. **Mobile (≤860 px) does not collapse**, retaining 78 vw horizontal snapping; collapse toggle not rendered on mobile.

## Evidence
- New `e2e/dx-16-board.spec.ts` (5 desktop+1 mobile): at 1440 with rail open, all six columns in Board, collapsed exactly 56 px, others > 120 px, Done present; strip click expands/collapses, Enter works; dragging into collapsed column expands/accepts card; collapsed "+ Add task" opens input; six headings retained; mobile six equal columns > 250 px, no horizontal overflow.
- Desktop/mobile regressions: `tasks` (existing `dragTo` included), `rehearsal`, `touch`, `a11y`, `word-budgets`, `activity-workspace`: **109 passed/11 intentional skips/0 failed**.
- **Negative verification:** clearing package styles fails 1 test (collapse assertions).
- `npm run lint` (style guard included) and typecheck passed; full integrated `npm run check` in stage 3 handoff, `docs/PROGRESS.md`.

## Notes
- **Tests caught two real issues:** ①I incorrectly assumed Done was empty; seed data contains a card, so changed test to first collapsed column; ②unstyled mobile collapse toggle became an extra button, caught by accessibility, now `display: none` on mobile.
- **Known limit (DX-24):** dragging across several empty columns expands each as traversed, pushing adjacent columns and causing jumps. Did not expand all columns during drag because it breaks Playwright `dragTo` destination calculation, used by existing tests. Revisit in DX-24 when pointer events replace native drag/drop.
- Minimum 120 px: six populated columns fit at 1440 with rail open (cards about 100 px), but narrowly; tradeoff between all visible and card width.
