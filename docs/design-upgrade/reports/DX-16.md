# 报告：DX-16 Tasks 看板版面：空列收窄、Done 列可见、卡片悬停

- 分支：`design/dx-16-board-layout`　执行：Claude，2026-11-01　回滚：R2（DX-21、DX-24、DX-26 依赖它，先撤它们）

## 做了什么
- `src/pages/Tasks.tsx`（只动看板）：没有任务的列折成 56px 的窄条（标题竖着写、一个 "+"），窄条自带一个"展开/收起"大按钮（`aria-expanded`，名字如 "Not claimed, no tasks. Show column"，Tab 可达）。拖到上面、点窄条、或有人在里面添加任务时展开。`+ Add task` 按钮名字**保持不变**（加了 `aria-label="+ Add task"`），现有测试靠它。六个 `h2` 都在。
- `src/styles/dx-16-board-layout.css`：电脑上看板改成 flex，列宽 `flex: 1 1 164px`、最小 120px，折叠列固定 56px，列宽过渡用 `--dur-base`（**这是本包唯一动画的布局属性**）；每列最小高度 `min(60vh, 520px)`（拖放目标够大）；卡片悬停时边框变强调色。**手机（≤860px）不折叠**，仍是 78vw 横向吸附，折叠开关在手机上根本不渲染。

## 证据
- 新测试 `e2e/dx-16-board.spec.ts`（电脑 5 个 + 手机 1 个）：1440 宽右栏打开时六列都在看板里，折叠列正好 56px、其余 >120px，Done 列存在；点窄条展开、再点收起，键盘 Enter 也行；把卡片拖到折叠列上，列展开且卡片落进去；折叠列里的 "+ Add task" 能点并展开出输入框；六个标题还在；手机上六列等宽 >250px、没有横向溢出。
- 回归（桌面 + 手机）：`tasks`（含现有的 `dragTo` 拖放）、`rehearsal`、`touch`、`a11y`、`word-budgets`、`activity-workspace`：**109 通过 / 11 按设计跳过 / 0 失败**。
- **反向验证**：清空本包样式，1 个测试变红（折叠相关的断言）。
- `npm run lint`（含样式守卫）和类型检查通过；阶段合并后的完整 `npm run check` 结果见 `docs/PROGRESS.md` 的阶段 3 交接。

## 要注意的地方
- **测试抓到两个真问题**：① 我假设 Done 列是空的，其实演示数据里它有卡片，测试写错了，改成"取第一个折叠列"；② 手机上折叠开关没有样式，变成一个多余的按钮，被无障碍检查抓到，现在手机上 `display: none`。
- **已知局限（留给 DX-24）**：拖一张卡横跨好几个空列时，每经过一个空列它就展开一次（旁边的列被挤开），位置会有点跳。我没有"拖动时展开所有折叠列"，因为那会让 Playwright 的 `dragTo` 落点算错列（现有测试靠它）。DX-24 把浏览器自带拖放换成指针事件后会重新处理。
- 最小列宽 120px：六列都有任务时，1440 宽右栏打开也放得下（卡片约 100px 宽），但会比较窄；这是在"全部可见"和"卡片宽度"之间的取舍。

## 合并后发现并修复的问题（看截图发现）
我把"每列最小高度 `min(60vh, 520px)`"写成了全局规则。手机没有拖放，结果手机上每个空列都成了一整块约 500px 高的灰色方块。**修复**：这条规则只在电脑（≥861px）生效；测试新增两条断言：手机上最矮的列 <260px，电脑上列高 ≥ `min(520px, 60vh)`。（我最初的说明书没有说明它只该用于电脑。）
