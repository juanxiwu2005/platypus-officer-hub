# 报告：DX-11 Toast 进出

- 分支：`design/dx-11-toast-motion`　执行：Claude，2026-11-01　回滚：R2

## 做了什么
- `src/components/chrome/Toast.tsx`：`useToast` 改成"出现 → 停留 2400ms → 淡出 → 卸载"；新消息在旧的还在时只替换文字并重新计时，**永远只有一个**；`data-state="open|closed"`；`role="status"` 和文案不变。
- `src/styles/dx-11-toast-motion.css`：从下方 8px 升起并淡入，淡出；底部加安全区；`max-width: calc(100vw - 96px)`。

## 证据
- 新测试 `e2e/dx-11-toast.spec.ts`（桌面 + 手机各 4 个）：逐帧看到淡入、上升（0–8px）、静止、淡出，3.1 秒内结束时已被移除；第二条消息不会叠出第二个 toast；手机上真实消息（"Demo data reset"）的右边缘在圆形按钮左侧（x<320）；"减少动效"下几乎立刻出现、最终被移除。加 `smoke`（Reset demo 后断言 toast 文案）：30 通过 / 0 失败。
- **反向验证**：清空本包样式，动效测试变红（1 个失败，其余断言本来就该过）。
- `npm run lint`（含样式守卫）和类型检查通过；阶段合并后的完整 `npm run check` 结果见 `docs/PROGRESS.md` 的阶段 2 交接。

## 要注意的地方
- 测试一开始写错了：在同一个浏览器任务里连点两次"Reset"，React 还没把按钮切到"Click again to reset"，第二次点击被当成第一次，toast 永远不出现。改成两次之间隔两帧。
- `max-width: calc(100vw - 96px)` 只对很长的消息有用；实际这条消息很短，所以不会盖到圆形按钮。
- **z-index 观察（没改）**：`--z-toast: 50` 低于 `--z-rail: 55`。手机上右栏全屏时 toast 会被盖住，但 toast 目前只由 Demo 菜单的 Reset 触发，而右栏打开时菜单够不到（页面 `inert`），所以现在碰不到这个问题。以后如果有别的地方触发 toast，需要整合人决定。
